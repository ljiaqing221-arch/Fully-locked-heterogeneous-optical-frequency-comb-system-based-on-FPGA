# 经验依据与迁移

## 项目中的观察
既有项目 testbench 通过不代表旧 routed 报告满足时序，更不代表光学实物性能。PID 抽取的绝对值需覆盖通用 18 位输入最小负数，不能只测原常见误差范围。

这些是源码、注释、既有测试或报告中的可核对观察；没有观测记录支持的情况不写成实物故障经历。

## 触发条件与定位
进程返回 0 但测试失败：同时查 PASS 和 fatal/error；旧 work 库污染：每个测试新建目录；相对路径漂移：以 manifest 所在目录解析；参数迁移后越界：增加极值和非整除测试；工具缺失：明确报告不可运行，不能伪造通过。

## 迁移检查
换项目先确认输入码制、有效信号、更新时钟、复位及输出协议，再替换接口。参数数值来自案例，不是对其他执行器或传感器的稳定性保证。原始来源清单与哈希见提交包 `validation/source_manifest.json`。

## 真实负例

原项目测试与当前扫描参数脱节，ModelSim 实际返回 smooth resonance valley was not detected。模拟器进程退出码仍为 0，运行器因 fatal 和缺少 PASS 正确判为失败。examples/known_failure.json 可重现；参数对齐后的对照版进入正常回归。该案例验证“退出码＋日志＋通过标志”必须共同判断。
